## In nutshell

Consists of a Value Neural Network (state $\rightarrow$ value) and Policy Neural Network (state $\rightarrow$ actions distribution) that are trained at the same time. Reward model is trained separately, with either human labeled data or verifiable answers (eg. math).

## Rewards

Rewards usually come from two sources: human feedback, or verifiable answers. For example:

**Human Feedback**

The human labeler is given the question and a list of answers for this question. He is then asked to rank the answers from best to worst. To learn what reward should be given to each of the answers, a separate reward model is trained. 

Question: "What color is the sky"?
1. "The sky is blue"
2. "The sky is red"
3. "The sky is banana"
4. "I like trains"

The ranking of answers allows us to train a reward model. The reward model will then be used to assing rewards to answers generated by the LLM for training questions. More on the reward model in the next section.

Slight tangent here: you may correctly think that getting this rankings, and then training a reward model, and only then having the data for PPO is lots of work. The authors of DPO probably thought so too, hence Direct Preference Optimization was born. For DPO, you only need a dataset containing triplets of (question, better response, worse response) to train the model. No ranking, no reward model, just choose the better answer and train.

**Verifiable Answers**

Works for domains when you can automatically check whether the answer is correct. Usually the reward is calculated as a combination of eg.: correct number, correct format (eg. latex), responding in domain or in the same language as the question. 

Question "2 + 2 ="

1. "2" $\rightarrow$ reward: +3
2. "0" $\rightarrow$ reward: +2
3. "The answer is 1" $\rightarrow$ reward: +1
4. "The only way to get gains is through testosterone injecton" $\rightarrow$ reward: -1 (penalization)

**Partial rewards**

This poses a natural question: "I only have rewards for my final states, how do I know how to reward states on my way to the final one?". Very good question, for that we just use a good ol' discounted reward.

If our final state has a value (reward) $R$:

$S_t =$ "The sky is blue"

$V(S_t) = R_t$

Then states leading to it, will share the final reward multiplied by the discount factor $\gamma$ to the power of $\rm{len}(S_t) - \rm{len}(S_{t-n})$ (in tokens) for the n-th state from the final state. Putting it into mathy word clouded how easy it is, lets look at second to last ("1-th") state:

$S_{t-1} =$ "The sky is"

$S_{t-1} = \gamma^1 \cdot R_t$

And one more step backwards ("2-th"):

$S_{t-2} =$ "The sky"

$S_{t-2} = \gamma^2 \cdot R_t$

For this to make sense, $\gamma$ has to be of course smaller than $1$, and we used the $\rm{word}=\rm{token}$ approximation.

## Policy and Value (and reward!) Networks

1. **Policy network:** LLM we want to train
2. **Value Network:** same LLM, with a regressive (single output) linear layer on top instead of the vocabulary sized layer (apparently, but I'm quite unsure, like how would that work for VERY large models? Tons of compute... not sure tho, also apparently the weights for shared layers are updated with both Value Network and Policy Network updates)
3. **Reward Network:** usually similar in architecture (same family, smaller) LLM, where the reward is obtained by putting the final token's hidden state through a single output (regressive) linear layer

Please remember that you do not need the reward model for verifiable domains. You would instead specify the heuristic with which to grade the answers. You might want to mix the heuristic with a reward model when you want to eg. grade some feature of the answer that is not verifiable (language maybe? not sure actually, style?)

## Training

Lets start assuming we have our reward model already trained, we will get back to it later. Below you will find a single iteration of the PPO training process. But what data do we use for that? We used our human labeled data to train the reward model (if you use a verifiable domain then I write this for nothing, so at least read it cause I had to write it), and now what? 

There are two ways: use the same questions as for the reward model training, or use questions from similar domain. Answers we of course don't need — we pass the question to the model, see what it outputs, and grade it with the reward model.

The main gist is that we compute the reward for a state (generated answer) with a reward model, the value (for the same answer) with the value network, compare the two, and update the value and policy networks based on the difference. How exactly? With the PPO loss function:

### Loss function (Courtesy of R1 and me)

Don't be scarred. 

#### Total Loss
The combined loss for PPO training:
$$
L^{\text{Total}} = \underbrace{L^{\text{CLIP}}}_{\text{Clipped Policy Loss}} - c_1 \underbrace{L^{\text{VF}}}_{\text{Value Loss}} + c_2 \underbrace{L^{\text{ENTROPY}}}_{\text{Entropy Bonus}}
$$

---

#### Expanded Terms

##### 1. Clipped Policy Loss
$$
L^{\text{CLIP}} = \mathbb{E}_t \left[ \min\left( r_t(\theta) A_t, \text{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon) A_t \right) \right]
$$

- **Probability Ratio**:

    Acts like a momentum, helping to either go down/up faster, or slow down when we overshoot.
  $$
  r_t(\theta) = \frac{\pi_\theta(a_t | s_t)}{\pi_{\text{old}}(a_t | s_t)}
  $$
  - **$\pi_\theta$**: Current policy (LLM).  
  - **$\pi_{\text{old}}$**: Policy before the update.  
  - **$a_t$**: Action (token) at timestep $t$.  
- **Advantage**:

    The difference between reward outputed for the answer by the reward model, and the value assigned by the value network.
  $$
  A_t = R_t - V_\phi(s_t)
  $$

- **Clipping**:

    Clipping for the "momentum" factor so we don't explode.
  $$
  \text{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon) = 
  \begin{cases}
    1+\epsilon & \text{if } r_t(\theta) > 1+\epsilon, \\
    1-\epsilon & \text{if } r_t(\theta) < 1-\epsilon, \\
    r_t(\theta) & \text{otherwise}.
  \end{cases}
  $$

##### 2. Value Loss
Trains the value network to predict returns accurately:

$$
L^{\text{VF}} = \mathbb{E}_t \left[ \left( V_\phi(s_t) - R_t \right)^2 \right]
$$

##### 3. Entropy Bonus
Encourages exploration by penalizing low entropy:

$$
L^{\text{ENTROPY}} = \mathbb{E}_t \left[ -\sum_{a} \pi_\theta(a | s_t) \log \pi_\theta(a | s_t) \right]
$$
- High entropy → More exploration.
- Low entropy → Overly deterministic policy.

---

#### Hyperparameters
- **$c_1$**: Value loss coefficient (e.g., 0.5).  
- **$c_2$**: Entropy coefficient (e.g., 0.01).  
- **$\epsilon$**: Clipping threshold (e.g., 0.2).  
- **$\gamma$**: Discount factor (e.g., 0.99).  

### Single iteration of PPO (courtesy of R1 and me)

1. **Policy Generates a Response**:  
   - **Input**: Prompt/question (e.g., *"Solve $2x + 3 = 7$"*).  
   - **Output**: Response (e.g., *"Subtract 3: $2x = 4$. Divide by 2: $x = 2$"*).  

2. **Reward Model Assigns $R_T$**:  
   - **Input**: Entire **(prompt, response)** pair.  
   - **Output**: Scalar reward $R_T$ (e.g., `+1` for correct, `0` for incorrect).  

3. **Compute Discounted Returns $R_t$**:  
   - For each token $t$ in the response, compute:  
     $$
     R_t = \gamma^{T-t} \cdot R_T
     $$  
     - $T$: Index of the final token.  
     - $\gamma$: Discount factor (e.g., $\gamma = 0.9$).  

   - **Example**:  
     - Final token $T$: $R_T = +1$.  
     - Token $T-1$: $R_{T-1} = 0.9 \cdot 1 = 0.9$.  
     - Token $T-2$: $R_{T-2} = 0.9^2 \cdot 1 = 0.81$.  

4. **Value Network Predicts $V(s_t)$**:  
   - The value network estimates the expected return $V(s_t)$ for each partial sequence (state $s_t$).  
   - **Example**:  
     - For token $T-1$ (*"Divide by 2: "*), $V(s_{T-1}) = 0.8$.  

5. **Compute Advantages $A_t$**:  
   - $A_t = R_t - V(s_t)$.  
   - **Example**:  
     - $A_{T-1} = 0.9 - 0.8 = +0.1$ → Positive advantage reinforces this token.  

6. **Calculate Loss and update the model**

### Pseudocode (just R1 for code)

This helped me the most in seeing the whole thing come to life. Once you slowly read the above (still probably being unsure about some implementation details), now take a look at the code below, and it shoud all make sense:

```python
import torch
import torch.nn as nn
from torch.optim import Adam

# Assume Policy (LLM) and Value Network share some layers (e.g., embeddings)
class PolicyValueNetwork(nn.Module):
    def __init__(self, base_model):
        super().__init__()
        self.base = base_model  # Shared transformer layers
        self.policy_head = nn.Linear(base_model.config.hidden_size, vocab_size)  # Token probabilities
        self.value_head = nn.Linear(base_model.config.hidden_size, 1)  # Scalar value

    def forward(self, input_ids):
        hidden_states = self.base(input_ids).last_hidden_state
        logits = self.policy_head(hidden_states)  # Shape: [batch, seq_len, vocab]
        values = self.value_head(hidden_states).squeeze(-1)  # Shape: [batch, seq_len]
        return logits, values

# Hyperparameters
clip_epsilon = 0.2
c1 = 0.5  # Value loss coefficient
c2 = 0.01  # Entropy coefficient
gamma = 0.99  # Discount factor
batch_size = 8
learning_rate = 3e-5

# Initialize model and optimizer
model = PolicyValueNetwork(pretrained_llm)
optimizer = Adam(model.parameters(), lr=learning_rate)

# Example training loop
for epoch in range(num_epochs):
    # Generate trajectories (states, actions, rewards)
    # Assume `generate_trajectories` returns:
    # - `input_ids`: tokenized prompts + responses [batch, seq_len]
    # - `actions`: token indices chosen by the policy [batch, seq_len]
    # - `old_logprobs`: log-probabilities under the old policy [batch, seq_len]
    # - `rewards`: discounted rewards per token [batch, seq_len]
    input_ids, actions, old_logprobs, rewards = generate_trajectories(model)
    
    # Forward pass: compute logits and values for all tokens
    logits, values = model(input_ids)
    logprobs = torch.log_softmax(logits, dim=-1)
    
    # 1. Policy Loss (Clipped Surrogate Objective)
    # Get logprobs for the chosen actions
    action_logprobs = logprobs.gather(-1, actions.unsqueeze(-1)).squeeze(-1)
    
    # Compute probability ratio: new_prob / old_prob
    ratios = torch.exp(action_logprobs - old_logprobs)
    
    # Compute advantages: A_t = R_t - V(s_t)
    advantages = rewards - values.detach()  # Detach values to stop gradient here
    
    # Clipped surrogate loss
    surr1 = ratios * advantages
    surr2 = torch.clamp(ratios, 1 - clip_epsilon, 1 + clip_epsilon) * advantages
    policy_loss = -torch.min(surr1, surr2).mean()  # Negative for gradient ascent
    
    # 2. Value Loss (MSE)
    value_loss = c1 * nn.MSELoss()(values, rewards)
    
    # 3. Entropy Bonus
    probs = torch.softmax(logits, dim=-1)
    entropy = -torch.sum(probs * logprobs, dim=-1).mean()
    entropy_bonus = -c2 * entropy  # Negative because we want to maximize entropy
    
    # Total Loss
    total_loss = policy_loss + value_loss + entropy_bonus
    
    # Backward pass & update
    optimizer.zero_grad()
    total_loss.backward()
    torch.nn.utils.clip_grad_norm_(model.parameters(), max_grad_norm=1.0)
    optimizer.step()
```
